🎯 Business Problem

💡 Key Challenge

How can we automatically analyze customer sentiment in real-time to predict and prevent churn before it happens?

Identify at-risk customers based on negative sentiment patterns

📡 Kafka Streaming

🎯 What is Kafka?

Apache Kafka is a distributed event streaming platform designed for:

  • High-throughput: Handles millions of messages per second
  • Low-latency: Sub-millisecond message delivery
  • Fault-tolerant: Data replication across multiple brokers
  • Scalable: Horizontal scaling by adding more brokers

🔍 Why Kafka for This Project?

⚡ Real-Time Streaming

Process reviews as they arrive, not in batches

🔄 Asynchronous Communication

Producer and consumer work independently

📊 Handles Millions of Messages

Scales to handle peak loads effortlessly

🛡️ Fault Tolerance

If one broker fails, others continue working

🏗️ Kafka Architecture Components

1️⃣ Producer (Publisher)

Role: Sends messages to Kafka topics

In our project: Reads Amazon reviews from CSV and publishes to reviews_raw topic

Rate: ~5 messages/second (configurable)

2️⃣ Broker (Kafka Server)

Role: Stores messages and serves them to consumers

In our project: Single broker running in Docker container

Scalability: Can add multiple brokers for high availability

Benefit: If one broker fails, others take over automatically

3️⃣ Consumer (Subscriber)

Role: Reads messages from Kafka topics

In our project: Spark Streaming consumes from reviews_raw topic

Processing: Enriches data with ML predictions and writes to MongoDB

📋 Kafka Topics in Our Project

Topic Name Purpose Producer Consumer
reviews_raw Raw review data from Amazon dataset Producer service Spark Streaming
reviews_enriched Reviews with ML predictions added Spark Streaming Dashboard (future), Analytics

🔄 Push-Pull Mechanism

How Kafka Works

Push (Producer → Broker):

  • Producer pushes messages to Kafka broker
  • Messages are stored in topic partitions
  • Producer doesn't wait for consumer to be ready

Pull (Broker → Consumer):

  • Consumer pulls messages from Kafka broker
  • Consumer controls the rate of consumption
  • Messages remain in Kafka even after being consumed (configurable retention)

💬 Messages and Topics

Communication Model

Topic: A category/channel where messages are published

Message/Event: A unit of data (in our case, a JSON review object). Each message is known as an event.

How it works:

  1. Producer writes a message (event) to a topic
  2. Kafka stores events in the topic
  3. Consumer reads events from the topic
  4. Multiple consumers can read the same events

📝 Code Example: Producer

# services/producer/app/producer.py from kafka import KafkaProducer import json # Create Kafka producer producer = KafkaProducer( bootstrap_servers="kafka:9092", value_serializer=lambda v: json.dumps(v).encode("utf-8") ) # Create review event def make_event(customer_id, text, channel): return { "event_id": str(uuid.uuid4()), "customer_id": customer_id, "product_id": product_id, "product_name": product_name, "text": text, "channel": channel, "timestamp_utc": datetime.now(timezone.utc).isoformat() } # Send message to Kafka topic event = make_event("C123", "Great product!", "web") producer.send("reviews_raw", value=event) producer.flush() # ✅ Message is now in Kafka, ready for Spark to consume!

🔑 Key Takeaways

  • Asynchronous: Producer doesn't wait for consumer
  • Decoupled: Producer and consumer work independently
  • Scalable: Can handle millions of messages
  • Reliable: Messages are persisted to disk
  • Real-time: Low-latency message delivery

🤖 Machine Learning Model

TF-IDF + Logistic Regression

Algorithm: TF-IDF (Term Frequency-Inverse Document Frequency) + Logistic Regression

Training: Pre-trained model using Amazon reviews dataset

Accuracy: 92%+ on test set

Classes: Positive, Neutral, Negative

Model Version: amazon_tfidf_lr_v1

📊 How TF-IDF Works

Text to Vectors Conversion

Problem: Machine learning models need numbers, not text

Solution: TF-IDF converts text to numerical vectors

  1. TF (Term Frequency): How often a word appears in a document
  2. IDF (Inverse Document Frequency): How rare/important a word is across all documents
  3. TF-IDF Score: TF × IDF = Importance of word in document

Example:

Review: "This product is amazing!"

→ Vector: [0.0, 0.8, 0.0, 0.6, 0.0, ...] (10,000 dimensions)

📝 Code Example: Spark Streaming

# services/spark_streaming/app/stream_job.py from pyspark.sql import SparkSession import requests # Create Spark session spark = SparkSession.builder.appName("Sentiment-Streaming").getOrCreate() # Read from Kafka raw_stream = spark.readStream \ .format("kafka") \ .option("kafka.bootstrap.servers", "kafka:9092") \ .option("subscribe", "reviews_raw") \ .load() # Call Model Service for predictions def get_predictions(rows): enriched = [] for row in rows: # Call Model Service API response = requests.post( "http://model_service:8000/predict", json={"text": row["text"], "event_id": row["event_id"]} ) pred = response.json() # Enrich row with predictions enriched_row = {**row} enriched_row["sentiment_label"] = pred["sentiment_label"] enriched_row["confidence"] = pred["confidence"] enriched_row["model_version"] = pred["model_version"] enriched.append(enriched_row) return enriched # Write to MongoDB and Kafka def enrich_and_write_batch(batch_df, batch_id): rows = batch_df.toJSON().collect() enriched_docs = get_predictions(rows) # Write to MongoDB db["reviews_enriched"].insert_many(enriched_docs) # Write to Kafka producer.send("reviews_enriched", value=enriched_docs) # Start streaming query = raw_stream.writeStream \ .foreachBatch(enrich_and_write_batch) \ .start() query.awaitTermination()

🔍 MongoDB Query Examples

// Find all positive reviews db.reviews_enriched.find({ sentiment_label: "positive" }) // Count negative reviews by channel db.reviews_enriched.aggregate([ { $match: { sentiment_label: "negative" } }, { $group: { _id: "$channel", count: { $sum: 1 } } } ]) // Find reviews for specific customer db.reviews_enriched.find({ customer_id: "C482" }) // Get average confidence by sentiment db.reviews_enriched.aggregate([ { $group: { _id: "$sentiment_label", avg_confidence: { $avg: "$confidence" } }} ]) // Find recent reviews (last hour) db.reviews_enriched.find({ timestamp_utc: { $gte: new Date(Date.now() - 3600000) } }).sort({ timestamp_utc: -1 })
